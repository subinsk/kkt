2. Problem Statements
Problem Statement 1: AI for Agriculture & Rural Communities
Build a real-time conversational AI experience that helps farmers, agricultural experts, field workers, cooperatives or rural communities communicate, access information or complete important workflows using voice. The solution should consider real-world challenges such as language diversity, code-switching, noisy environments, limited typing, low digital literacy or difficulty accessing experts. The objective is not to build a simple voice-based crop information bot. Teams should explore how conversational AI can make agricultural services more accessible, contextual and actionable.
Teams may explore:
Multilingual farmer assistance
Code-switched conversations
Agricultural advisory
Farmer-to-expert escalation
Crop or equipment support
Cooperative workflows
Market or availability information
Voice-based data collection
Field-worker assistance
Agricultural service discovery
Government scheme navigation
Voice-based workflow automation
Farmer onboarding
Follow-up reminders
Structured case creation
The solution should demonstrate:
Natural real-time voice interaction
Interruption handling
Session-level conversational memory
Dynamic questioning based on user responses
At least one external data source, API or tool
At least one visible external action
Clear handling of uncertainty
Human or expert escalation where appropriate
Support for realistic language or field conditions
Example scenario: A farmer begins speaking in Hindi and explains that something unusual is happening with a crop. The AI asks follow-up questions rather than immediately generating an answer. The farmer switches between Hindi and English while describing the situation. The AI retrieves relevant contextual information and determines that an expert should review the case. The system creates a structured case containing the information collected during the conversation and initiates an expert follow-up. The farmer does not need to repeat the entire problem.
Innovation opportunity:
Vernacular interaction and code-switching
Low-literacy interfaces and contextual questioning
Human escalation and voice-based workflows
Knowledge retrieval and field-data integration
Conversation design and handling incomplete information

3. Mandatory Requirements
1. Centrality of Agora Conversational AI: The project must use Agora Conversational AI for the primary live voice interaction between the user and the AI agent. Using Agora only for a secondary, decorative or non-essential feature will not qualify.
2. Voice-Native Solution: The project must solve a problem that benefits meaningfully from continuous live conversation. A text chatbot connected to speech-to-text and text-to-speech without proper conversational behaviour will receive a low score. The experience should demonstrate characteristics such as natural speaking, interruption, follow-up questions, context retention, dynamic conversation flow, appropriate silence, clarification, and voice-triggered actions.
3. Live Prototype Demonstration: The final submission must include a working live demonstration. Judges must be able to interact with the AI rather than only watch a prerecorded workflow.
4. Interruption Handling: The user must be able to interrupt or redirect the agent while it is speaking. The AI should stop appropriately, understand the interruption, and continue naturally from the new direction.
5. Conversation State Maintenance: The AI should remember and use relevant information shared earlier in the same session (e.g., user preferences, requirements, previous answers).
6. External Action Integration: The voice agent must do more than answer questions; it must perform at least one meaningful external action (e.g., create a ticket, book an appointment, retrieve external information, update a database).
7. Dynamic Conversation Flow: The agent should not rely entirely on a predefined sequence of questions. The conversation should change depending on user responses, missing information, retrieved data, previous context, confidence, external-system responses, user interruptions, or changed requirements.
8. Human Escalation Path: For experiences involving uncertainty, complaints, sensitive decisions, or situations requiring expertise, teams should provide a path to a human, preserving relevant context.
9. Defined AI Limitations: Every submission must clearly explain what the AI can and cannot do, what information it has access to, when it asks clarifying questions, when it requires user confirmation, when it escalates to a human, how it behaves when uncertain, and what happens when an external API fails.
4. Conversational AI Depth Requirements
Teams must implement at least five conversational capabilities, such as barge-in, natural turn-taking, code-switching, noise handling, and recovery from corrections.
